## 🔍 The Problem

As a tertiary educator, I'd built up a large collection of teaching resources over the years — but my only way of storing and sharing them was a Pinterest board, which was clunky to search and didn't allow categories or notes.

I couldn't find a site that did what I needed: a simple, searchable database of adult learning resources that could be shared across a team or institution.

So I built one.

---

## 👩‍💻 My Role

Solo developer and designer. Self-sponsored project completed as part of my Micro-Credential in Software Development (Level 5/6) at Open Polytechnic NZ.

I drew on my background as a tertiary educator to inform the user personas, use cases, and stakeholder considerations — designing for the kind of institutions and tutors I'd worked alongside.

---

## 🎯 Target Users

- Tertiary educators and tutors looking for adult learning resources
- Educational institutions wanting a shared, searchable resource hub
- Admins needing to manage and update content from the front end

## ⚙️ The Process

I used an **iterative SDLC**, planning requirements from use cases first, then building in cycles and adjusting scope as I learned what was feasible.

Key milestones:
- Defined user personas, use cases, and acceptance criteria
- Built and connected the database, then layered in search and category functionality
- Shifted from MySQL/EJS to React/Firebase mid-project when course requirements changed — which meant rebuilding the app from scratch in a new framework
- Used manual white box testing throughout, documenting test cases and known bugs honestly

---

## ✅ Outcome

A working MVP with:
- Searchable resource database
- Category browsing
- Resource submission form
- Firebase hosting and image storage
- Documented test cases and known limitations

---

## 💪 Challenges

The framework shift mid-project was the biggest hurdle — I hadn't used React before and the course materials had errors in the example code, so I had to find my own path through.

I found a working template with a similar structure to what I needed, dissected it to understand how React projects fit together, and adapted it from there. I also used ChatGPT to help identify bugs and understand syntax — which accelerated my learning significantly once I started using it.

---

## 🔁 What I'd Do Differently

- Budget more time upfront for learning a new framework before building in it
- Comment code more thoroughly from the start
- Learn terminal and implement GitHub branches and commits properly, rather than manual version control via zipped folders
